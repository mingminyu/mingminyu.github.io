作为一款对标 Claude Code、Codex 的顶尖 Agent，DeekSeek Harness 实战开发性能到低如何？四个字评价，强到离谱。本次课程将带你手把手搭建一款功能完整、性能强劲的工业级 LLM Wiki 知识库。知识库不仅拥有样式美观的工作台 Dashboard，而且完成的文档管理、编译、上传等功能，同时支持查阅 Wiki 编译结果以及提供增量文档编译功能，并且能查看完整的、双形态的知识图谱。此外，知识库可以进行可溯源的知识库问答，任何回复都能关联到原始知识片段，也支持系统在线评估和优化，可根据检索命中率、证据覆盖率等问题进行编译方式和检索流程优化，当然还有完整的系统功能设置页面。

最关键的是，从搭建开发环境到最终完成项目开发，我们总共就只对 DeepSeekHarness 进行 10 轮专业提示，外加 8 个 Skills、一套 Agent 预设（Preset）以及两个功能插件。整个开发过程异常稳定，效率极高，个人觉得甚至超过了 Codex 和 Claude Code 的开发体验。

本套课程带你真正掌握 DSH 工业开发实战技巧，彻底释放 DSH 性能潛力。目前这项 LLMWiki 知识库也正式上线了我们团队自研的 DeepspSeek Harness 桌面端。此外，LLM Wiki 源码、Agent Preset预设、开发知识库、Skills 和架构图、主轮提示词、对话运行截图和阶段性开发成果截图等全套学习资料可以在赋范 AI 社区进行免费下载。

作为一门零基础的课程，首先我们将通过一组示例，为大家详细介绍今年大火的 LLM Wiki 知识库到低是什么，整个资料的采集、编译、问题、增量更新的流程是怎么执行的，手把手带大家搭建好基础开发环境。

实践中我们发现，要用好 DSH 就必须要根据实际开发目标对 DSH 进行功能组装，例如组装一些插件、Skills 和 Agent 预设（即 Agent模式）等。本次 LLM Wiki 开发任务，我们装配了一系列用于对齐意图、补充信息以及辅助开发的 Skills。此外，我们还需要安装 `dsh-diagram` 和 `dsh-builtin-browser` 这两款插件，前者用于辅助绘制流程图随时查看系统架构，后者则负责辅助进行产品页面的功能验收。

我们还专门设置了一个 Agent 预设，可以把它理解是一个为了本次开发工作单独创建的 Agent 模式，用于严格执行 LLM Wiki 项目开发工作流，以及灵活调用相关插件和 Skills 等。这个 Agent 预设功能堪称 Deepseek Harness 最强隐藏功能，用好它能让你的 Agent 性能跨越式提升。

整个 LLM Wiki 是一个相对比较复杂的开发项目，需要经历如下共 11 个阶段的开发。

| 阶段 | 上一状态缺少什么 | 本阶段形成的直接结果 |
| --- | --- | --- |
| STAGE-01 | 工作区、模型、权限与视觉能力尚未统一 | 首条开发 Prompt 之前的共同运行基线 |
| STAGE-01 | 空目录没有可运行的产品 | monorepo、共享合同、WEB/API 股价和满载工作台 |
| STAGE-02 | 每轮都要重新强调工程纪律 | 可重复选择的 `LLM Wiki 全栈工程师` Preset |
| STAGE-03 | 首页有统计数据，但资料不可操作 | 资料搜索、筛选、分页、导入、失败、重试和详情闭环 |
| STAGE-04 | 原始资料仍按各自作者的叙事存在 | 可重建、可引用、可互链的编译式 Wiki |
| STAGE-05 | Wiki 页面还不是稳定图数据 | 可重复生成的节点、边与检查器合同 |
| STAGE-06 | 节点边已存在，但最小交互链未验证 | 消费真实 API 数据的基础 SVG 图谱 |
| STAGE-07 | 团队缺少统一的系统图 | 可编辑、可导出的架构沟通资产 |
| STAGE-08 | 基础图谱难以识别的关键关系 | 同一数合同上的正式图谱体验 |
| STAGE-09 | 用户能阅读知识，但不能提问并检查数依据 | 检索、流式回答、引用联动与无证据拒答 |
| STAGE-10 | 零散试问无法形成质量判断 | 固定题库、指标、基线、优化与回归门 |
| STAGE-11 | Agent 自报完成不能作为交付依据 | 浏览器全链路、工程验证、截图和接手文档 |

我们会详细介绍每个阶段输入的提示词

```markdown title="完整Prompt"
我们现在从零开始建设一个面向企业资料的“LLM Wiki工业知识库”系统。先不要一次性堆叠所有AI能力，这一轮只把工程底座和第一个可运行页面搭稳，为后续资料处理、知识编译、图谱和问答模块建立可扩展边界。

技术约束：
1. 使用 pnpm workspace, Node.js 24+；目录至少包含 apps/web、apps/api、packages/contracts。
2. Web 使用 Next.js 16、React 19、TypeScript、Tailwind CSS； API 使用 Fastify、TypeScript；本地数据层预留 SQLite。
3. 根目录提供统一的 dev、build、typecheck、test 脚本，以及 `.env.example` 和中文 README。
4. 首页先做成可用于日常运营和阶段验收的深色知识工作台：左侧产品导航，顶部项目标题和状态，主区域包含 “文档数、知识条目、关系数、今日问答” 四张统计卡、最近文档列表和处理进度。先使用来源统一、可追溯的预置业务数据，确保系统首次启动即可验证完整信息架构。
5. 同时创建文档、Wiki、知识图谱、智能问答四个路由入口，但这一轮允许后三个使用清晰的阶段占位页。
6. API 先提供 `/health` 和 `/api/overview` 两个接口；前端首页优先读取API，API 不可用时用同结构预置数据兜底，并清楚标识当前数据状态。
7. 页面要有工业感但不沉闷，使用蓝紫色高光、半透明面板、细网格背景和克制的动效；响应式至少覆盖 1440px 桌面和 768px 平板。
```
