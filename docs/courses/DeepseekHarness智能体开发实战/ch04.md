# 第四章： 从空目录搭起第一个可运行的LLM Wiki

## 1. 工程目标与完整Prompt

上一模块结束时，DSH Studio 中已经存在一个“空白但就绪”的开发环境：课程开发 Session 指向独立 Workspace，已经选中 “LLM Wiki全栈工程师” Preset，产品代码尚未创建，模型、访问模式和视觉增强也已经完成核对。此时不需要重新安装 Preset、Skills 或 Plugins，也不应把最终源码复制进项目目录。真正需要解决的问题，是把 “从零建设企业LLM Wiki” 这个过于宽泛的目标，收敛成一轮边界清楚、结果可观察、失败可继续处理的工程任务。

第一轮只建立工程底座，而不同时实现资料解析、Wiki编译、知识图谱和问答。原因并不是这些能力不重要，而是后续功能都依赖一组共同边界：前端与后端放在哪里，共享数据结构由谁定义，项目怎样统一启动与验证，后端暂时不可用时页面怎样如实降级。若这些边界尚未建立就直接堆叠 RAG、图谱算法和模型调用，任何错误都可能同时跨越数据、服务与界面三层，学员既难以定位原因，也无法判断某个页面究竟来自真实服务还是预置展示。

### 1.1 发送前确认任务位置

主 Prompt 应发送到上一模块已经核对过的同一个课程开发 Session。课程实操只有一个执行口径：继续使用该 Session 已经选中的 “LLM Wiki全栈工程师” Preset，不切换到“标准模式”;发送前只需复查Workspace、模型、工作区写入和视觉增强仍与上一模块的就绪状态一致。后文截图中的“标准模式”属于历史STAGE-01开发回放状态，用于识别当时的界面与过程，不是需要照抄的课程设置。
