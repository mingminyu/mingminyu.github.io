# 从入门到进阶：封装一个 Skill

> Skill 不是插件，也不是一段提示词：**一个目录 + 一份 `SKILL.md`**，把每次都要重新交代的流程、口径、脚本与模板，打包成可被自动触发的能力。

元数据常驻上下文，正文触发时才加载，脚本与资料按需取用 —— 这套 ==渐进式披露== 决定了 Skill 该写多少、该把什么拆出去。

## 1. 先看结构：三层加载

| 层级     | 内容                                 | 何时进入上下文    | 体量        |
| ------ | ---------------------------------- | ---------- | --------- |
| L1 元数据 | `name` + `description`             | 常驻，决定要不要触发 | 约 100 词   |
| L2 正文  | `SKILL.md` 指令                      | 技能被触发时     | 建议 < 5k 词 |
| L3 资源  | `scripts/` `references/` `assets/` | 按需加载或直接执行  | 不限        |

!!! note "为什么分层"

    元数据回答「用不用」，正文回答「怎么用」，资源只在真正需要时取用。把几万字的 API 文档塞进 `SKILL.md`，等于每次触发都先付一遍上下文成本。

```text
skill-name/
├── SKILL.md            # 必需：YAML frontmatter + Markdown 指令
├── scripts/            # 可选：确定性脚本，可直接执行，不必读入上下文
├── references/         # 可选：按需读入的 schema / API / 规范
└── assets/             # 可选：产出物要用的模板、图片、字体
```

## 2. 入门实例：20 行的最小 Skill

场景：每次写周报都要重复交代字段、百分比、金额口径。把它固化成 `weekly-report-style`：

```markdown
---
name: weekly-report-style
description: 统一周报的输出口径与字段格式，用于生成或整理项目周报、复盘周报、数据周报。当用户要求「写周报」「整理本周进展」「汇总回收率数据」时使用。关键词：周报、进展同步、复盘、回收率、口径。
agent_created: true
---

# 周报口径

## Overview

把周报固定为「进展 / 数值 / 风险 / 下一步」四段，统一百分比与金额写法。

## 输出规则

- 百分比保留 1 位小数并标注升降方向；涨用红色语义、跌用绿色语义。
- 金额统一用 ¥ 千分位，不写币种缩写。
- 每条进展必须带一个可核对的数值；没有数值就写「待补数据」。
- 不写套话，不推测未给出的数据。

## 工作流程

1. 确认周期与数据范围。
2. 按四段输出，数值只取自用户材料，缺失字段显式标注。
3. 输出前逐条核对数值与单位。
```

| 字段              | 必填      | 作用                 | 约束                                                      |
| --------------- | ------- | ------------------ | ------------------------------------------------------- |
| `name`          | 是       | 唯一标识，须与目录同名        | hyphen-case：小写字母 / 数字 / 连字符，≤ 40 字符，不以 `-` 开头结尾、不含 `--` |
| `description`   | 是       | 唯一的触发依据            | 第三人称；写清「做什么 + 何时用 + 用户会说的词」；不含尖括号                       |
| `agent_created` | 是（本机约定） | 允许后续用技能管理命令修改 / 删除 | `true`                                                  |

!!! warning "description 是触发器，不是简介"

    写「周报相关」既会在无关任务里误触发，也常在真正需要时不触发。把用户可能说出口的原话写进去。

| 反例                           | 正例                                            |
| ---------------------------- | --------------------------------------------- |
| `处理周报`                       | `统一周报口径……当用户要求「写周报」「整理本周进展」时使用。关键词：周报、复盘、口径。` |
| `This skill helps with data` | 写明具体场景、文件类型、触发词，并用第三人称描述                      |

## 3. 入门实例：四步做出第一个 Skill

```bash
S=/Applications/WorkBuddy.app/Contents/Resources/app.asar.unpacked/resources/plugins/workbuddy-builtin/skills/skill-creator/scripts

# 1. 生成骨架（同时创建 scripts/ references/ assets/ 三个示例文件）
python3 "$S/init_skill.py" weekly-report-style --path ~/.workbuddy/skills

# 2. 编辑 SKILL.md，并删除用不到的示例文件（此处应全部删掉，只留 SKILL.md）

# 3. 校验结构
python3 "$S/quick_validate.py" ~/.workbuddy/skills/weekly-report-style

# 4. 打包分发（先自动校验，再产出 zip）
python3 "$S/package_skill.py" ~/.workbuddy/skills/weekly-report-style ./dist
```

| 步骤    | 脚本                  | 产出 / 检查                                                   |
| ----- | ------------------- | --------------------------------------------------------- |
| 1 初始化 | `init_skill.py`     | 目录 + 模板 `SKILL.md` + 3 个示例文件                              |
| 2 编辑  | —                   | 补全 `description`、删 TODO、删多余目录                             |
| 3 校验  | `quick_validate.py` | `SKILL.md` 存在、frontmatter 完整、`name` 合规、`description` 无尖括号 |
| 4 打包  | `package_skill.py`  | `weekly-report-style.zip`，zip 内保留技能目录层级                   |

=== "用户级（默认推荐）"

    `~/.workbuddy/skills/<name>/`：跨所有项目可用，适合个人口径、别名映射、常用流程。范围不明确时一律选它。

=== "项目级（团队共享）"

    `<workspace>/.workbuddy/skills/<name>/`：随仓库走，适合团队约定、项目 schema、共用工作流。

!!! tip "本机实测：`--path` 必须显式给"

    skill-creator 的说明把 `--path` 写成「可省略、默认用户级」，但本机 `init_skill.py` 的 `main()` 要求参数 ≥ 4 个且第 3 个必须是 `--path`；省略会直接打印用法并退出。上面四步命令已在 /tmp 实测通过：初始化 → `Skill is valid!` → `demo-skill.zip`。

## 4. 进阶实例一：`scripts/` 把确定性逻辑固化

真实案例 `~/.workbuddy/skills/bilibili-video-info/`：解析 B 站分享文本 / 短链，输出标题、时间、UP 主、规范 URL。

```text
bilibili-video-info/
├── SKILL.md
├── scripts/
│   ├── resolve_bili.py          # 302 跳转、BV 提取、元数据格式化
│   └── uploader_aliases.json    # UP 主名称映射（数据与逻辑分离）
└── references/
    └── bilibili_api.md          # 接口字段、响应示例、错误码
```

使用时不重写代码，直接执行脚本，把用户原文整段传进去：

```bash
python3 ~/.workbuddy/skills/bilibili-video-info/scripts/resolve_bili.py "【手指发力技术教学-哔哩哔哩】 https://b23.tv/HlWsuVM"
```

`SKILL.md` 只写「何时用、怎么调、失败怎么降级」，例如：

```markdown
优先执行 `scripts/resolve_bili.py`，把用户原文整段作为位置参数传入，不需要手工清洗；脚本自动跟随 302 跳转、提取 BV 号、读取 `scripts/uploader_aliases.json` 完成名称映射。字段映射与响应示例见 `references/bilibili_api.md`。
```

| 做法                | 原因                                        |
| ----------------- | ----------------------------------------- |
| 脚本可直接执行，不必读入上下文   | 省 token、结果确定、可复测                          |
| 映射表 / 配置与脚本逻辑分离   | 改数据不改代码；同一条规则只存在一处                        |
| 降级路径写进 `SKILL.md` | 本机直连 API 常被拦截，固定走「WebFetch 取 JSON → 喂回脚本」 |
| 缺失字段显式标注「未获取」     | 防止模型凭猜测补齐                                 |

## 5. 进阶实例二：`references/` 与 `assets/` 的取舍

| 目录            | 放什么                      | 判据                | 别放           |
| ------------- | ------------------------ | ----------------- | ------------ |
| `scripts/`    | 可执行的 Python / JS / Shell | 同一段代码被反复重写，或需要确定性 | 纯说明文档        |
| `references/` | schema、API 文档、规范、政策      | 执行时才需要查的知识        | 每次都必读的核心流程   |
| `assets/`     | pptx 模板、HTML 骨架、图片、字体    | 会被复制进最终产物         | 需要「读进上下文」的说明 |

!!! tip "大文件与去重"

    单份 reference 超过约 10k 词时，在 `SKILL.md` 里写明 grep 搜索模式，让执行方按需定位片段。同一条信息只在 `SKILL.md` 或 `references/` 出现一次：正文留「何时用 + 怎么用」，细节放参考资料，避免两处不一致。

更完整的组合案例 `~/.workbuddy/skills/italent-attendance-capture/`：

```text
italent-attendance-capture/
├── SKILL.md
├── config.json
├── scripts/
│   ├── capture.js          # 浏览器抓取、逐条截图、去重
│   └── excel_report.py     # 加班台账写入与汇总
└── references/
    └── workflow.md         # 参数优先级、长区间耗时、降级说明
```

```bash
node ~/.workbuddy/skills/italent-attendance-capture/scripts/capture.js \
  --start 2026-11-01 --end 2026-11-06 --out ./attendance-shots
```

关键数值：30 条/页分批、18:00 判定加班、`captured.json` 记录已抓日期实现幂等、stdout 返回摘要 JSON。这类「多脚本 + 状态文件 + 参考文档」的结构，正是从单文件 Skill 升级到可长期运行工具的分界线。

## 6. 进阶实例三：让 Skill 越用越准

| 观察到的现象       | 改哪里                                                                       | 怎么验证        |
| ------------ | ------------------------------------------------------------------------- | ----------- |
| 从没被触发        | `description` 补场景与用户原话                                                    | 用真实提问复测     |
| 触发后做错步骤      | `SKILL.md` 补边界、顺序、降级流程                                                    | 重跑同一任务      |
| 每次都重写同一段代码   | 下沉到 `scripts/`                                                            | 直接执行脚本      |
| 上下文被长文档挤占    | 移到 `references/` 并给 grep 模式                                               | 观察是否只加载必要片段 |
| 规则两处不一致      | 只保留一处（数据放 JSON，规则放 `SKILL.md`）                                            | 全局搜关键词      |
| 市场安装的技能被更新覆盖 | 保存编辑后在 `_skillhub_meta.json` / `_knot_meta.json` 写 `"userModified": true` | 检查 meta 文件  |

写作用的固定口径：用祈使句 / 不定式（「执行 X」「把 Y 传入 Z」），不用第二人称；只写对另一个实例 ==非显而易见== 的知识，不复述常识；`SKILL.md` 里引用到的每个资源都要说明何时使用。

## 7. 发布前校验清单

- [ ] `name` 与目录名一致，且为 hyphen-case
- [ ] `description` 含「做什么 / 何时用 / 触发词」，无尖括号
- [ ] `agent_created: true` 已写入 frontmatter
- [ ] 正文只留核心流程，长文档已拆到 `references/`
- [ ] `example.py` / `api_reference.md` / `example_asset.txt` 已删除或替换
- [ ] `quick_validate.py` 输出 `Skill is valid!`
- [ ] 用真实任务跑过一遍，必要时回到第 6 节迭代
- [ ] `package_skill.py` 打出 `<name>.zip`

## 8. 常见坑速查

| 坑                               | 后果               | 修法                      |
| ------------------------------- | ---------------- | ----------------------- |
| 省略 `--path`                     | 初始化直接退出          | 显式带 `--path`            |
| `name` 与目录名不一致、含大写或下划线          | 校验失败 / 无法被管理     | 目录与 `name` 同步改名         |
| `description` 太泛或含尖括号           | 误触发、不触发、校验失败     | 场景 + 触发词，去掉尖括号          |
| 忘写 `agent_created: true`        | 后续无法用管理命令修改 / 删除 | 补字段                     |
| 规则在 `SKILL.md` 与脚本 / JSON 里各写一份 | 改一处漏一处，行为漂移      | 数据归数据，流程归正文             |
| 初始化示例文件没删                       | 打包把占位文件一起分发出去    | 用不到的目录整个删掉              |
| 把整本 API 文档塞进正文                  | 每次触发都撑爆上下文       | 拆到 `references/` 并给检索模式 |
